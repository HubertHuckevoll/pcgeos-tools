# BbxBrow globe resource lifetime

- The Show Globe Logo option (`HTMLV_SHOW_GLOBE`) changes the usability of `SpinningLogo` through `UpdateGlobeInSimpleButtonToolbar`/`UsableOrNot` in `Appl/Breadbox/BbxBrow/htmlview/HTMLViewOptions.goc`, then requests `MSG_HMLVA_UPDATE_GLOBE`. Operation startup uses the same application message (`htmlview/HTMLViewOperation.goc`): its 40-tick timer runs only when `HVAI_operationLevel` is nonzero and the gadget is usable. The former `globeOff` INI key is no longer read; visibility controls whether animation is allowed. Hiding stops animation; showing during a load can resume it. `MSG_HMLVA_END_OPERATION` stops animation when the last operation ends. The globe policy has a host check in `tests/check_globe_animation.pl`.
- `htmlview/GlobeAnimation.goc` puts the 15 uncompressed 32x32 RGB frames from `Art_Globe/globe1.goh` through `globe15.goh` in separate data resources. Each bitmap contains 3078 bytes including its six-byte header. Drawing locks only the selected resource and unlocks it afterward; stopping or hiding does not free loaded frames.
- These resources have no explicit attributes in `bbxbrow.gp`. `Tools/glue/geo.c:GeoPrepare` defaults non-object LMem resources to `RESF_SWAPABLE|RESF_DISCARDED|RESF_LMEM`: initially unloaded, subsequently swappable, but not discardable. Do not interpret DISCARDED (initial state) as DISCARDABLE (ongoing eviction permission).
- Unloaded resources still consume kernel handles: `Library/Kernel/Geodes/geodesLoad.asm:ProcessGeodeFile`/`AllocateResource` allocates a handle for each resource, even when `HF_DISCARDED` suppresses allocating its contents. `Include/Internal/heapInt.def:HandleMem` is 16 bytes. The core block additionally keeps eight bytes of resource tables per resource (`GH_resHandleOff`, `GH_resPosOff`, `GH_resRelocOff` in `geodesLoad.asm`).
