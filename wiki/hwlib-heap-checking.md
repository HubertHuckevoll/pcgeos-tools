# Heap Walker checksum hooks

- The browser history calls this "Heap Walker Checksum checking" and says it was added for debugging and disabled, under the 04/02/98 Lysle entry (`Appl/Breadbox/BbxBrow/notes/WHATSNEW.TXT:1625`). Browser and Html4Par options describe it as "strong heap checking".
- `CInclude/hwlib.h` declares `_cdecl HWChecksumCheck(void)`, `HWLowMemCheckOn(void)`, and `HWLowMemCheckOff(void)` only when `DO_HW_CHECKSUM_CHECKING` is defined. Otherwise all three are empty function-like macros. This switch is independent of `ERROR_CHECK`; defining it to zero still enables the declarations because the header uses `#ifdef`.
- Enabling the hooks requires both the preprocessor switch before the first inclusion of `hwlib.h` and a `library hwlib` import in each calling geode. See `Appl/Breadbox/BbxBrow/options.goh`, `prodbbx.goh`, `bbxbrow.gp`, and `Library/Breadbox/Html4Par/options.goh`, `html4par.gp`. These switches/imports are commented out. The inspected source/build trees contain the header and callers but no hwlib implementation or link/runtime library; its checking coverage and failure behavior cannot be established from the hooks.
- GEOS has a separate native single-block checksum facility: `SysSetECLevel` sets `sysECBlock` and clears `sysECChecksum` in the EC kernel (`Library/Kernel/Sys/sysMisc.asm`). `ECF_BLOCK_CHECKSUM` enables `ECCheckBlockChecksum` (`Library/Kernel/Heap/heapErrorCheck.asm`), which sums 16-bit words over the resident block's paragraph-sized extent, maps zero to one, stores an initial checksum, and reports `BLOCK_CHECHSUM_ERROR` on mismatch. There is no established connection to hwlib.
- Swat's `ec sum <handle>` / `ec -sum` controls that native facility. Setting/removing software breakpoints in a monitored resource changes its checksum; disable checking first, change the breakpoints, then re-enable it (`Tools/swat/lib.new/ec.tcl:132`, command documentation).
