Write a concise PR description for an experienced maintainer.

Start with a short paragraph explaining the user-visible change and its purpose. Then use a few focused bullets describing the implementation, naming the relevant functions, messages, fields, and constants. Link directly to those functions in the actual source using GitHub permalinks with line anchors.

Give related fixes a brief introductory sentence so their purpose is clear.

Include enough accompanying prose to connect the changes, but avoid a walkthrough, obvious details, promotional language, and unnecessary headings. Aim for about 150–200 words, excluding URLs.

Don't finish with a compact validation paragraph stating what passed and what remains untested!
